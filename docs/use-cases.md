# 使用场景

Lark Resume 适合把飞书中的真实工作上下文转成可确认、可追溯、面向岗位的个人材料。以下示例均为脱敏的虚构场景。

## 1. 产品经理简历

**输入上下文：** 产品需求文档、评审群聊、项目周会纪要、上线复盘。

**生成重点：**

- 产品方向和业务问题；
- 需求拆解、权限设计、流程设计和跨团队推进；
- 已上线能力和可验证的业务结果；
- 面向目标岗位调整项目顺序和能力表述。

**示例请求：**

```text
请根据我在飞书里的产品工作记录生成中文简历，先给 brief，任职时间 2024-03 至今，最终格式 HTML。
```

## 2. Agent 开发工程师简历

**输入上下文：** Agent runtime 设计讨论、工具调用问题排查、评测记录、发布说明和代码评审。

**生成重点：**

- Agent 架构、工具调用、状态管理和执行链路；
- 可观测、可回放、评测和线上稳定性；
- 从原型到工程化交付的个人贡献；
- 技术栈、工程复杂度和结果边界。

**示例请求：**

```text
请根据我在飞书里的 Agent 项目记录生成一份英文简历，直接生成 Markdown，任职时间 2023-06 至今。
```

## 3. 企业交付 / 解决方案简历

**输入上下文：** 客户需求群、交付计划、会议纪要、问题跟进记录、验收材料。

**生成重点：**

- 客户场景和业务约束；
- 方案设计、风险处理、跨团队协调和交付节奏；
- 已验收或已落地内容；
- 对外表达时隐藏客户敏感信息。

**示例请求：**

```text
请根据我在飞书里的客户交付记录生成中文简历，先生成 brief，最终格式 DOCX。
```

## 4. 内部转岗材料

**输入上下文：** 当前团队项目、跨团队协作记录、OKR、任务和内部评审材料。

**生成重点：**

- 当前岗位的真实工作范围；
- 与目标岗位相关的能力证据；
- 代表项目中的个人价值；
- 保留内部可理解的项目背景，但避免泄露敏感细节。
